# kakugo（覚悟シート）

仕事で使ってきた型を、プライベートに移す。元にしたのは factory の10ステップ（`~/factory/workflow/WORKFLOW.md`：番号→imozuru→KGI→SPEC→提案→ロック→REA）で、次のように置き換えた。

| factory | kakugo | 変えた理由 |
| --- | --- | --- |
| 番号・依頼 | テーマ1つ | 決断を1つに絞らないとパターンが発散する |
| REA（一番よい実例を逆解析） | **本人の仕事の型を、本人の記録から逆解析**（`METHOD.md`） | 移したい「一番よい実例」は本人の仕事のやり方そのもの。外の方法論は補助 |
| imozuru（実例調査） | `saiaku`（imozuru で web から**現実に起きた最悪**を原文ごと集める）＋足りない頻度だけ imozuru | 想像の最悪でなく現実の最悪から選ぶ。頻度で「覚悟の要る最悪」と「起きにくい心配」を分ける |
| KGI | **覚悟の基準**（何が残れば良しとするか） | 仕事のKGIに当たる。判定の物差し |
| SPEC・ROADMAP | **覚悟シート**（パターン×兆候×資源の消費×連鎖×対応策）と、**組み合わせのシナリオ**ごとの判定 | 最悪は重なって来る。判定はパターン1つでなく組み合わせに付ける |
| 提案→修正→ロック | 本人が読み、直し、確定版をcommit | |
| テスト | シートの点検（下の「点検」） | |

順番は REA を先にする。仕事の型が先に分からないと、プライベートに何を移すかが決まらないため。

## 守ること（先に読む）

1. **気持ち・覚悟は本人の言葉だけ。** 「その時どう感じそうか」「受け入れるか」は AI が書かない。空欄なら空欄のまま残す。AIが書いてよいのは、パターン案・頻度・体験談・本人の記録からの引用（出典つき）
2. **相手を動かす策を対応策にしない。** 相手は自分の思い通りにならない前提で、対応策は「自分がどうするか」で書く。相手への働きかけは「自分が言う・頼む」まで
3. **調べすぎない。** imozuru は「頻度か体験談で判定が変わりうる」パターンだけ。1パターン原文3〜5本で止める
4. **自分が起こさない・自分に関係の薄いパターンは外す。** 外したものと理由は残す（後で戻せるように）
5. **プライバシー。** 検索語・imozuru のフォルダに本人や相手の名前・固有の事情を入れない（「国際カップル 帯同 離婚率」の粒度）。シートは `private/kakugo/` だけに置く。コーチへ共有する版は、開示の程度を本人が選ぶ（10/1〜6 の日記抜き出しと同じやり方）。送るのは本人
6. **本人が強く反応したものは、その場で `<テーマ>-<日付>/REACTIONS.md` に追記する**（本人 2026-10-27「今回の調査プロジェクトで私が強く反応したパターンを固有のファイルに記録しといてほしい。これはこの調査中常にやって」）。本人が自分から足したパターン、指摘、評価、自己理解を、原文と時刻の順で残し、どこに反映したかを書く。AI の読みは【推論】と分ける
7. 出典の区別: 【本人】本人発言・記録 /【原文】imozuru の原文 /【推論】AI の推論。頻度は出典か「仮定」を必ず付ける

## 置き場

`private/kakugo/`

- `METHOD.md` … 本人の仕事の型（一度作って使い回す。テーマごとには作らない）
- `<テーマ>-<YYYY-MM-DD>/KAKUGO.md` … そのテーマの覚悟の基準とシート
- 調査の原文: `~/research/kakugo-<テーマの一般名>/`（imozuru の置き場の決まりどおり）

`the records checkout` の編集は worktree で（`.claude/rules/worktree-first.md`）。

## 手順

### 0. テーマを1つ決める（質問は1つまで）

本人の依頼からテーマを1文にする（例:「◯◯に住むか決める」「この人と長く一緒にいるか決める」の型）。依頼で分かるなら聞かない。決まっていなければ、`private/todo.md`・直近の日記（`private/journal/entries/`）・CoachEd の記録（`private/meetings/`）から候補を2〜3出して1つ選んでもらう。

### 1. 仕事の型を取り出す（REA相当・初回だけ）

`METHOD.md` が無いときだけ作る。あれば読んで使う（本人が型を直したときだけ更新）。

1. 記録を固定する: 本人が最悪を想定して決めた仕事・お金の判断を、本人の記録から3〜5件選ぶ。ファイルパスと、読んだ時点の commit（`git log -1 --format=%h -- <path>`）を記録する。候補の探し方:
   `grep -rln -E "最悪|ワースト|覚悟|ストレス" private memory docs | grep -v snapshots`
   （候補の例: 資産配分の生活費ストレスケース、UBS構造のストレステスト、退任合意書の対応。数字はスキルに書かず METHOD.md に引く）
2. 各件から、次を読み取る。どれも【O】記録にある／【I】推論／【U】不明 を付け、行番号つきで引く
   - 最悪をどう列挙したか（何個・何の軸で）
   - 最悪の大きさをどう測ったか（金額・確率・期間）
   - 「受け入れる」と決めた線と、「これだけは避ける」と決めた線
   - 事前に打った手（予防）と、起きたときの手（修復）
   - 決めた後どう動いたか（迷いを止めた・蒸し返さない等）
3. `rea-agents` について: REA はコード・アプリ・バイナリを読む道具で、人の判断の記録は読めない。`METHOD.md` に「REA: not applicable - 対象が判断の記録でありコードではない」と書き、REA の決まり（対象の固定・digest・[O]/[I]/[U]・"無い"と"見ていない"を分ける）だけを使う
4. 外の方法は補助として1段落だけ並べる（imozuru の起点語に使う）: 事前検死（premortem / prospective hindsight）、fear-setting（define / prevent / repair、やらないことのコスト）、ストア派の premeditatio malorum。本人の型と違う点だけを書く
5. 最後に「仕事とプライベートで違う点」を1つの節にする。少なくとも次を検討する: 仕事は相手（会社・市場）を条件で縛れるが、プライベートは縛れない／仕事は撤退が選択肢だが、プライベートは撤退が相手を傷つける／仕事の大きさは金額で測れるが、プライベートは測れない。本人の記録で裏付けが無い点は【推論】と書き、本人に確かめる

### 2. 覚悟の基準を決める（KGI相当）

`KAKUGO.md` の冒頭に、本人の言葉で書く。AIは問いを出すだけ。

- このテーマで、最悪の場合でも**何が残れば「やってよかった」と言えるか**
- **絶対に避けたいこと**は何か（これが起きるなら最初からやらない、の線）
- いつまでに決めるか

本人が答えられないときは、仕事の型（`METHOD.md`）で同じ問いにどう答えていたかを1つ見せて聞き直す。それでも出なければ空欄で次へ進み、手順5で戻る。

線は「やりたいことの一覧」に対して引かない。やりたいことは生きていれば増えるので、一覧で測ると新しく出てきたものが守れない（本人 2026-10-27）。代わりに、**新しいやりたいことが出てきたとき、それを遅れてでも始められるだけの自由が残るか**で測る。自由は3つの資源で数える:

- **お金**: 自分が自由に使える額（年あたり・一時）
- **時間**: 自分が自由に使える時間（週あたり）と、それが何年続くか
- **決める自由**: 一人で決められる範囲（住む場所・お金の使い方・仕事・時間の使い方のうち、誰かの同意が要るようになったもの）

それぞれ「ここを下回ったら、新しいことを始められない」線は、本人に聞かずに AI が調べて案を出す（本人 2026-10-27「お願いの1~3は調査して欲しい。今後の生活を考えて」）。材料は2つ:

- 本人の今後の生活の記録: 生活費の基準とストレス、資産と取り崩しの規律、計画中のやりたいこと（留学・移住など）の費用・時間・滞在の条件（`private/資産運用/`、`research/case0-*`、auto-memory）
- 外の事実: 子育ての時間と費用（本人の帯で）、結婚・親権が住む場所・お金・子の移動の決め方をどう縛るか（法令の条文・公的統計。原文を `~/research/<テーマ>/lines/` に保存）

線は「本人の記録の規律から導いた数字（出典つき）」として書き、AI の推論の部分は【推論】と書く。本人は確かめて直すだけにする。

### 3. 最悪のパターンを出す

1. 候補は web の原文から集める: `saiaku` スキル（`skills/saiaku/SKILL.md`）を背景エージェントで、テーマの一般名と**本人の条件の帯**（資産の帯・住まい方・関係の形・年代。`private/` の記録から作り、名前や固有の事情は入れない）を渡して走らせ、`patterns.md` を候補にする。そこに本人の記録（発言・日記）にある心配を【本人】として足す。軸は次の7つを一度ずつ見て、どれにも候補が無い軸だけ AI が【推論】で足す: 相手（気持ち・裏切り・病気・死）／自分（気が変わる・病気・能力）／子ども・家族／お金／住む場所・制度（ビザ等）／評判・法律／時間（何年も決まらない・機会を逃す）
2. 本人が選ぶ: 残す／外す（理由）／足す。本人の「すげえいろんなこと考えちゃう」を止めないために、外す理由は「自分が起こさない」「自分に関係が薄い」「起きても覚悟が要らない」の3つから選ぶだけでよい
3. 残す数に上限は付けない（本人 2026-10-27「あらゆるパターンを広く考えたい」）。同じものだけまとめる。上限は手順5bの組み合わせのシナリオにだけ付ける

### 4. 頻度と体験談を集める（imozuru・必要な分だけ）

この手順は既定では飛ばす。統計の有無で判定を変えないため（本人 2026-10-27「統計は別に大丈夫」）。本人が統計を求めたときだけ行う。体験談・立て直しの違いは、手順3の `saiaku` の `patterns.md` にもう入っている。ここでは、本人が残したパターンのうち、`patterns.md` で頻度が「見つからず」か当事者の原文が無い（【本人】【推論】で足したもの）ものだけ、しかも「頻度か体験談で判定が変わりうる」ものだけを、同じ research フォルダで imozuru に渡す。map.md の論点は次の3つにする:

- そのパターンが現実に起きる頻度（統計・研究。母集団と測り方つき）
- 起きた当事者が、そのとき何を感じ、何をして、どうなったか（体験談・インタビュー・フォーラム。一人称の原文）
- 立て直せた人と立て直せなかった人で、何が違ったか

1パターン原文3〜5本で止める。頻度が見つからなければ「仮定」と書いて進む。調べている間はこちらで要約せず、シートに入れるときに引用と出典で入れる。

### 5. 覚悟シートを作る

パターンごとに次の欄。【AI】の欄だけ AI が埋める。【本人】の欄は質問して本人の言葉を入れる（1パターン2〜3往復まで。journal の対話契約と同じく、話の途中で割り込まない・既に答えたことを聞かない）。

| 欄 | 書き手 | 中身 |
| --- | --- | --- |
| 状況 | AI→本人が直す | 何が起きるか、1〜2文 |
| 兆候 | AI | 起きる前に見えるサイン（体験談から） |
| 頻度・大きさ | AI | 出典つきの数字か「仮定」 |
| その時どう感じそうか | **本人** | |
| 予防（事前の手） | AI案→本人 | 自分がやること。費用・手間つき |
| 修復（起きた後の手） | AI案→本人 | 自分がやること。最初の24時間・1か月・1年 |
| 重さ | 気持ち＝**本人**、ほかは AI（原文か仮定） | コストの3軸: **気持ち**（本人の感情）・**お金**・**労力**（解決にかかる手間・時間）。本人 2026-10-27「俺の気持ちの問題と金の問題と法的な問題の３つ…それと労力も関連する」 |
| 降りられなさ | AI（原文か仮定） | 自分の意思で撤退・拒否できない度合いと、その原因: **法的**（争われて負ける、同意が要る、知らないルールの下に置かれる）／**道徳的**（生計を一にする家族の生活を崩す）／**物理的**（子の障害・病気など、法も無いが離れられない）。本人の「法的」を広げた軸（2026-10-27 本人 go） |
| 続く長さ | AI（原文か仮定） | 重さと降りられなさが何年続くか。取り消せるか（子は取り消せない） |
| 連鎖 | AI（原文） | このパターンの後に起きやすいパターン、一緒に起きやすいパターン（`patterns.md` の連鎖の欄） |

パターン1つずつには判定を付けない。1つでは自由が残っても、重なると残らないことがあるため（本人 2026-10-27。仕事の型2「最悪は同時に起きる形で作る」と同じ）。判定は次の手順5bで、組み合わせに付ける。

### 5a. 共通の手を調べる（imozuru＋REA。AI の推論だけで作らない）

パターンが多いと、1件ずつの対処法では追いつかない（本人 2026-10-27「対処法が難しいやつすごい多いね」）。仕事のストレステストと同じく、少数の手で多くのパターンを受ける。ただし手は AI の推論で作らず、原文から集める（本人 2026-10-27「君の推論のみでやるのやだな。同様にimozuruとREAを使って調査したい」）。

1. **imozuru で手を集める**（背景エージェント、`~/research/<テーマ>/levers/`）。問い:「このテーマの最悪に対して、実際に人や専門家が事前・事後に打った手は何で、効いたか、どこで効かなかったか」。論点: 手の名前と仕組み（どこで、誰が使うか）／実際に使った人の原文と結果／効かなかった・覆された例（裁判で無効にされた契約など）／専門家の枠組み（実務家・研究・公的な手引き）／本人の条件の帯（資産・多拠点・国をまたぐ）で使えるか。Codex の `codex exec` にも同じ問いを独立に回し（`levers-codex/`）、見落としを比べる
2. **REA で一番よい実例を読む**: 手のうち一番根拠のある「仕組み」（例の型: 公的な手引き、法令、契約の雛形、判決、家族の憲章の公開例）を固定し、sha256 を取り、条や節ごとに【O】/【I】/【U】で読む。`rea-agents` はコードとバイナリを読む道具なので、文書には「REA: not applicable - 文書でありコードではない」と書いて、REA の決まり（固定・digest・O/I/U・「無い」と「見ていない」を分ける）だけを使う。仕組みがソースコードやアプリ（家計・資産管理の道具など）なら `rea-agents` をそのまま使う
3. `LEVERS.md` に、手ごとに: 名前／事前か事後か／払うもの（お金・時間・自由）／効くパターン（M番号）／根拠（【原文】file:行 か REA の読み。根拠の無い手は書かない）／効かなかった例。どの手も効かないパターンは「覚悟だけ」として全部並べる。手そのものが本人の線（やりたいことを奪われない）とぶつかるものは別に書く

### 5b. 組み合わせで判定する（ストレスシナリオ）

1. **組み合わせを選ぶ。** 全部の組み合わせは数えない。次の3つで選び、多くて5本にする
   - **連鎖**: 原文で「続けて起きた」と書かれた並び（例の型: Aが起き → その負担でBが起き → Cに至る）
   - **同じ資源の取り合い**: 同じ資源（例: 時間）を大きく取るパターンどうしが同じ時期に重なる
   - **本人が心配する重なり**
2. **基準・ストレス・最悪の3段にする**（`METHOD.md` 型1）。基準＝悪いことが何も起きなくてもかかる重さ（例: 育児そのものの労力・時間・お金。本人 2026-10-27「育児それ自体に取られるリソース」）と、そのテーマでふつうに起きること、ストレス＝基準＋連鎖1本、最悪＝ストレス＋同じ資源を取る別のパターン
3. **年表で資源を足し上げる。** シナリオごとに、年ごとのお金・時間・決める自由の残りを表にする（消費は各パターンの「資源の消費」から。仮定は仮定と書く）。足し算と比較はAIがやり、数字の元をすべて書く
4. **判定（本人）**: 手順2の線と比べて、そのシナリオで **自由が残る**／**残らない**。残らないシナリオでは、どの時点で線を割るかと、連鎖のどこを切れば（どのパターンの予防・修復を先に打てば）線の上に戻るかを AI が示し、本人がその手を取るかを決める
   - **残る**: そのシナリオは覚悟済み。予防・修復をそのまま置く
   - **切れば残る**: 切る手が覚悟の中身になる（「この連鎖が見えたら、ここで◯◯する」と先に決める。`METHOD.md` 型4）
   - **切っても残らない**: テーマ自体を考え直すか、そのシナリオを受け入れるかを本人が決める。めったに起きないこと（ブラックスワン）も、起きにくさを理由に外さない（本人 2026-10-27「ブラックスワンでも起きたらインパクトあるから」）

最後に、本人に2問だけ聞く:「切っても残らない」シナリオは、手順2の「絶対に避けたいこと」と同じか／判定を見て、テーマへの決断は変わったか。

### 6. 点検（テストに当たる）

本人に見せる前に、次を全部確かめ、通らない所は直すか `[要確認]` を付ける:

- 【本人】の欄に AI の文が入っていない（空欄は可）
- 頻度に出典か「仮定」がある。出典は `~/research/...` の原文か本人の記録を指している
- 対応策の主語が自分。相手を変える策が混ざっていない
- 外したパターンと理由が残っている
- 曜日つきの日付は `date` で確かめた
- 検索語・research フォルダに個人名・固有の事情が無い

### 7. 本人が読む → 直す → 確定

- 本人に見せる（ターミナルで全文。不在なら `ask-me.py --tell` でファイルの場所と要点だけ。本文は送らない）
- 新しいパターン・条件が出たら、その点だけ手順4へ戻る
- 本人が「これで確定」と言ったら commit（worktree の手順）。以後の変更は日付つきで追記し、確定版を書き換えない

### 8. コーチと共有する版（CoachEd の宿題のとき）

- 開示の程度を本人に1問で選んでもらう（例: A 全部／B 相手は仮名・お金と性的な具体は省く／C 判定と気づきだけ）
- 書く前に、共有版の要件を決めて本人に直してもらう。出典は、コーチが宿題を出したときの言葉（文字起こし）と本人の言葉。最初の要件は「初見のコーチが5分で、何をして何が分かり、本人がどう感じ、セッションで何を話したいかが分かる」こと。調査の索引や法令の表を本文にしない（付録へ）（2026-10-27 本人「初見の人がこれを見てどうなるの？」）
- 本人に見せる前に、Codex に「初見のコーチ」として敵対的にレビューさせ、指摘を直す
- 選ばれた版を `<テーマ>-<日付>/coach-share.md` に作る。PDF が要るなら本人の Downloads へ出す
- 送るのは本人。エージェントがメール・メッセージで送るときは通常の承認の流れ（`mail-send-approval.md`）

### 9. 振り返り（あとで）

セッションの後、またはパターンのどれかが現実に起きた・起きかけたとき、そのパターンに「実際」の欄を追記する: 何が起きたか／想定と違った点／覚悟は持ったか。`METHOD.md` の「仕事とプライベートで違う点」に新しく分かったことがあれば足す。
